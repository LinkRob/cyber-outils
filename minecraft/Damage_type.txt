'''Damage types''' are [[JSON]] files located in [[data pack]]s that define different kinds of damage that entities can take. They control which attributes the damage has as well as which death message is used when an entity dies due to that type of damage.

Additionally, the built-in [[Tag#Damage types|damage type tags]] control many aspects of how damage is applied by the game.

Custom damage types can currently only be applied using the {{cmd|/damage}} command.

==File format==
Damage types are stored as [[JSON]] files within a [[data pack]], at the path <code>data/<namespace>/damage_type/<name>.json</code>.

<div class="treeview">
*{{nbt|compound}} The root object.
**{{nbt|string|message_id}}: Used as part of the [[death messages|death message]] translation key if {{nbt|string|death_message_type}} is set to {{cd|default}}, as shown [[#Default message type|below]].
**{{nbt|float|exhaustion}}: The amount of hunger [[exhaustion]] caused by this damage type.
**{{nbt|string|scaling}}: Whether this damage type scales with [[difficulty]].<br>Possible values: {{cd|never}}, {{cd|always}}, or {{cd|when_caused_by_living_non_player}}. See [[#Scaling|below]] for more detail.
**{{nbt|string|effects}}: Optional field controlling how incoming damage is shown to the player.<br>Possible values: {{cd|hurt}} (default), {{cd|thorns}}, {{cd|drowning}}, {{cd|burning}}, {{cd|poking}}, {{cd|freezing}}. See [[#Effects|below]] for more detail.
**{{nbt|string|death_message_type}}: Optional field that controls the kind of death messages to use.<br>Possible values: {{cd|default}} (default), {{cd|fall_variants}}, {{cd|intentional_game_design}}. See [[#Death messages|below]] for more detail.
</div>

For example, here is JSON for the built-in {{cd|minecraft:arrow}}:<syntaxhighlight lang="json">
{
	"exhaustion": 0.1,
 	"message_id": "arrow",
	"scaling": "when_caused_by_living_non_player"
}
</syntaxhighlight>

==Scaling==
Damage types control whether damage scales with [[difficulty]].{{info needed|how exactly does damage scale?}}

Possible values of {{nbt|string|scaling}}:
*{{cd|never}}: Damage is always the same.
*{{cd|always}}: Damage always scales with difficulty.
*{{cd|when_caused_by_living_non_player}}: Damage scales with difficulty if the attacker<ref group="note" name="attacker">The entity that was responsible for the damage. Also known as the "source entity". For example, if a player is shot by a skeleton, the skeleton is the attacker. If a player is shot by a [[dispenser]], the arrow itself is the attacker. If the player is pricked by a cactus, there is no attacker.</ref> was a living entity<ref group="note" name="living">This includes [[armor stand]]s.</ref> and was not a player.

==Effects==
Damage types control how incoming damage is shown to the player.

Possible values of {{nbt|string|effects}}:
*{{cd|hurt}} (default): The default hurt sound.{{Sound||Player hurt1.ogg|Player hurt2.ogg|Player hurt3.ogg}}
*{{cd|thorns}}: [[Thorns]] hurt sound.{{Sound||Thorns1.ogg|Thorns2.ogg|Thorns3.ogg|Thorns4.ogg}}
*{{cd|drowning}}: [[Drowning]] sound.{{Sound||Player hurt drowning1.ogg|Player hurt drowning2.ogg|Player hurt drowning3.ogg|Player hurt drowning4.ogg}}
*{{cd|burning}}: A single tick of [[Fire|burning]] sound.{{Sound||Player hurt fire1.ogg|Player hurt fire2.ogg|Player hurt fire3.ogg}}
*{{cd|poking}}: [[Berry bush]] poke sound.{{Sound||Player hurt sweet berry bush1.ogg|Player hurt sweet berry bush2.ogg}}
*{{cd|freezing}}: [[Powder Snow#Freezing|Freezing]] tick sound.{{Sound||Player hurt freeze1.ogg|Player hurt freeze2.ogg|Player hurt freeze3.ogg|Player hurt freeze4.ogg|Player hurt freeze5.ogg}}

==Death messages==
Damage types control the [[death messages]] displayed when players or pets die.

Possible values of {{nbt|string|death_message_type}}:
*{{cd|default}} (default): Use the standard death message logic.
*{{cd|fall_variants}}: Use the fall damage death messages, e.g. <code>death.fell.assist.item</code>.
*{{cd|intentional_game_design}}: Show the "intentional game design" death message.

===Default message type===
When standard death message logic is being used, messages are generated as follows, making use of the {{nbt|string|message_id}} tag:

* If the killing blow was caused by an attacker<ref group="note" name="attacker" /> and the attacker was holding a named [[item]] in their main hand at the time of death, this is categorized as an item death. A [[Raw_JSON_text_format#Translated_Text|translated message]] is displayed using the translation key <code>death.attack.<message_id>.item</code> with the following insertions available:
*# The name of the dying entity.
*# The name of the attacker.
*# The name of the item.
* If the killing blow was not caused by an attacker<ref group="note" name="attacker" />, but the dying entity had recently{{info needed|how recently?}} taken damage that <em>was</em> caused by a living entity<ref group="note" name="living" />, this is categorized as an assisted death. A [[Raw_JSON_text_format#Translated_Text|translated message]] is displayed using the translation key <code>death.attack.<message_id>.player</code> with the following insertions available:
*# The name of the dying entity.
*# The name of the recent attacker.
* If neither of the above apply, this is categorized as a normal death. A [[Raw_JSON_text_format#Translated_Text|translated message]] is displayed using the translation key <code>death.attack.<message_id></code> with the following insertions available:
*# The name of the dying entity.
*# The name of the attacker<ref group="note" name="attacker" />, if there was one.

==Design==
Because of how the default death messages are set up, most vanilla damage types are divided into ones that will always have an attacker<ref group="note" name="attacker" /> and ones that will never have an attacker. Depending on whether there was an attacker, the translation for normal deaths (<code>death.attack.<message_id></code>) will have either one or two available insertions. Translations have no safe way to access an insertion that may or may not be there, so the primary options are:

The death type is planned to always have an attacker.
* The translation looks like<syntaxhighlight lang="json">
"death.attack.mob": "%s was slain by %s",
"death.attack.mob.item": "%s was slain by %s using %s",
</syntaxhighlight>
* The translation key <code>death.attack.<message_id>.player</code> is not provided, since assisted deaths are impossible.

The death type is planned to never have an attacker.
* The translation looks like<syntaxhighlight lang="json">
"death.attack.drown": "%s drowned",
"death.attack.drown.player": "%s drowned whilst trying to escape %s",
</syntaxhighlight>
* The translation key <code>death.attack.<message_id>.item</code> is not provided, since item deaths are impossible.

The death type may or may not have an attacker.
* The translation looks like<syntaxhighlight lang="json">
"death.attack.electricity": "%s was electrocuted",
"death.attack.electricity.item": "%s was electrocuted by %s using %s",
"death.attack.electricity.player": "%s was electrocuted whilst trying to escape %s",
</syntaxhighlight>
* The translation key <code>death.attack.<message_id></code> avoids using the second insertion, since it may or may not be present.
* The translation is a little awkward, since the death message when killed by a player will only mention them if they're holding a named weapon.

To avoid the awkwardness of the third option you can have two different damage types, one for use with an attacker, and one for use without an attacker:<syntaxhighlight lang="json">
"death.attack.active_electricity": "%s was electrocuted by %s",
"death.attack.active_electricity.item": "%s was electrocuted by %s using %s",
"death.attack.passive_electricity": "%s was electrocuted",
"death.attack.passive_electricity.player": "%s was electrocuted whilst trying to escape %s",
</syntaxhighlight>
