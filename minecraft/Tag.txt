{{update|Bedrock tags now exist.}}
{{About|data pack and behavior pack tags|other uses|Tag (disambiguation)}}

'''Tags''' in [[data pack]]s{{only|je|short=1}} and [[behavior pack]]s{{only|be|short=1}} allow players to group different game elements together.

==Usage==
===Java Edition===
To utilize block, item, function tags, etc., the JSON files must be placed in a data pack inside a respective folder or its subfolder in the <code>data/(namespace)/tags</code>. The folders' names are listed below.

{|class="wikitable"
|+ List of tag folders
|-
!Registry entries !!Registry !!Tag folder
|-
|Blocks ||{{cd|minecraft:block}} ||{{cd|data/''namespace''/tags/blocks}}
|-
|Fluids ||{{cd|minecraft:fluid}} ||{{cd|data/''namespace''/tags/fluids}}
|-
|Items ||{{cd|minecraft:item}} ||{{cd|data/''namespace''/tags/items}}
|-
|Entity types ||{{cd|minecraft:entity_type}} ||{{cd|data/''namespace''/tags/entity_types}}
|-
|Game events ||{{cd|minecraft:game_event}} ||{{cd|data/''namespace''/tags/game_events}}
|-
|Others ||See [[Resource location]] ||Folder in {{cd|data/''namespace''/tags}} with the same path with the registry's resource location.<br>For example biomes' tag is in {{cd|data/''namespace''/tags/worldgen/biome}}.
|}

One exception is '''function tag'''. Functions are not registry entries, but function tags can be defined at {{cd|data/''namespace''/tags/functions}}.

Tags are not only used by players. ''Minecraft'' itself also uses tags. For example, vanilla block tags are used for various block behaviors, vanilla item tags are used for various item behaviors, vanilla [[advancement]] files and vanilla [[recipe]] files, and vanilla entity type tags are used for various mob behaviors. See [[#List of tags]] section for their usages.

====Resource location====

The resource location of a tag is also in the format of <code><namespace>:<path></code>, where namespace is the name of the folder that the <samp>tags</samp> folder is in, and path is the JSON file's path under the respective tag folder.

For example, JSON file <samp>data/wiki/tags/blocks/foo/example.json</samp> defines a block tag with the resource location of <code>wiki:foo/example</code>.

To distinguished normal contents from tags, a “#” is usually required before tag's resource location.

====JSON format====

<div class="treeview">
*{{nbt|compound}} The root object.
**{{nbt|boolean|replace}}: Optional. Whether or not the contents of this tag should completely replace tag contents from different lower priority data packs with the same resource location. When <code>false</code> the tag's content is appended to the contents of the higher priority data packs, instead. Defaults to <code>false</code>.
**{{nbt|list|values}}: A list of mix and match of object names and tag names. For tags, recursive reference is possible, but a circular reference causes a loading failure.
***{{nbt|string}}: An object's [[resource location]] in the form {{cd|(resource location)}}.
***{{nbt|string}}: ID of another tag of the same type in the form {{cd|#(resource location)}}.
***{{nbt|compound}}: An entry with additional options. (1.16.2+)
****{{nbt|string|id}}: A string in one of the string formats above.
****{{nbt|boolean|required}}: Whether or not loading this tag should fail if this entry is not found, true by default (also for the string entries). A tag that fails to load can still be referenced in any data pack and be (re)defined in other data packs. In other words, only the entries in this JSON file are ignored if this entry cannot be found.
</div>

====Block tags====
[[Block]] tags can be called when testing for block arguments in commands with <code>#<resource location></code>, which succeeds if the block matches any of the blocks specified in the tag. 

====Item tags====
[[Item]] tags can be called when testing for item arguments in commands with <code>#<resource location></code> or in recipes and advancements using <code>"tag": "<resource location>"</code>, which succeeds if the item matches any of the items specified in the tag. They can also be searched in the creative inventory by searching {{cd|#<resource location>}}.

====Entity type tags====
[[Entity]] type tags can be called in [[Target selectors#Selecting targets by type|<code>type</code> target selector argument]] and loot table conditions with <code>#<resource location></code>, which checks if the entity's type matches any of the entity types specified in the tag.

====Function tags====
{{anchor|Function Tags}}
[[Functions|Function]] tags can be called in the {{cmd|function}} command with <code>#<resource location></code>, which runs all the functions specified in the tag in the order of their first appearance in a tag. If a function is referenced multiple times in a tag and its sub-tags, it is run once.

Moreover, functions tagged in the <code>minecraft:tick</code> tag run every tick at the start of the tick and functions tagged in <code>minecraft:load</code> run once at the start of the tick after a server (re)load.

===Bedrock Edition===
Tags are defined in the block's, item's, and biome's behavior as follows:
<div class="treeview">
*{{nbt|compound}} The root object.
**{{nbt|compound|minecraft:(block{{!}}item{{!}}biome)}}
***{{nbt|compound|components}}
****{{nbt|compound|tag:<''tag''>}}: (Blocks and items) <code><''tag''></code> is replaced by the name of the tag. Object must be empty.
****{{nbt|compound|<''tag''>}}: (Biomes) <code><''tag''></code> is replaced by the name of the tag. Object must be empty.
</div>
A block, item, or biome may have multiple tags. Custom and vanilla tags are authorized.

Tags can be used to run queries in commands and behavior packs.

====Block tags====
There is currently no vanilla [[block]] with a tag with any properly/real use.

====Item tags====
[[Item]] tags can be called in recipes using <code>"tag": "<''tag''>"</code>, which succeeds if the item has the tag.

====Biome tags====
[[Biome]] tags can be called using <code>"minecraft:biome_filter": { "test": "has_biome_tag", "operator": "<''operation''>", "value": "<''tag''>" }</code> for the entity's spawn rules (biomes), which succeeds if the biome has the tag.
